# 工程周报整理

## 核对本周工作

- 以用户给定的项目、日期和要点为准。只说“本周”时，按用户时区取周一至当天。用户给了提纲时，以提纲为骨架，补上有证据的结果。
- 核对本周相关分支的 Git 提交、必要的代码差异，以及报告和测试记录。浏览可读取的项目相关 Codex 或 Copilot 对话，补足提交标题省略的问题、解决办法和实验结论。其他项目和往周事项只用作背景，除非本周有明确进展。
- 用提交或差异确认改动，用测试报告或实验记录确认效果。明确是静态核对、主机测试、仿真还是台架实测。计划、可选方案和待验证事项按实际状态写。对话来源缺失时先用可用材料完成，只有缺失影响结论时才简短说明。

## 写成可直接粘贴的周报

- 用「本周工作总结（M 月 D–D 日）」作标题，再列编号要点。通常 3–6 条，按独立成果归并；同一项工作的排查、修正和验证可以放在一起。
- 每条以粗体短标题开头，接一到两句，先写做了什么，再写解决了什么问题或验证到了什么结果。用项目已有术语，省略逐条提交、工具调用过程和泛泛评价。
- 优先保留少量能说明效果的数字。注明适用工况、单位和验证范围。对比结果优先写前后值；若只有结论，按实际记录写。保留会影响读者理解的待测项、适用限制或代价，可在相关条目末尾附关键报告链接。

示例条目：

> **PWM 移植修正**。核对三相 12 路 PWM 的引脚映射，修正下桥臂 Buck、Boost 输出极性互换。L1 台架实测确认零点及正负满量程电平符合预期。
